# Splunk Enterprise 10.x Architecture & Release Matrix (10.2.x → 10.6.x)

> [!summary] Executive Summary
> This consolidated technical reference aggregates all major architectural evolutions, core capabilities, breaking changes, and upgrade trajectories across the **Splunk Enterprise 10.x** product lifecycle, spanning versions **10.2.x** through **10.6.x**.

## 🔍 Detailed Version Breakdown

### 1. Splunk Enterprise 10.6.x
> [!info] Core Focus: Platform Engineering Automation, On-Prem Audit & 4-Segment Versioning
* **Unified 4-Segment Versioning Scheme:** Standardized format `Major.Minor.Maintenance.Patch` (e.g., `10.6.4.1`).
* **Data Management Service APIs:** Official, supported REST APIs to automate Edge Processor and Ingest Processor pipeline provisioning via CI/CD.
* **Cloud-Aligned Configuration Change Tracking:** Built-in audit trail recording actor identity, timestamps, `.conf` files modified, and execution status (`success`/`failure`) on on-premise Web UI & REST endpoints.
* **App Management & Low Downtime:** ~50% reduction in platform restart requirements upon app deletion (`[reload_on_delete]` in `limits.conf`).
* **Federated Search Handshake:** Automated capability verification preventing runtime query errors across hybrid distributed Search Heads.
* **AI Assistant "Agent Mode":** Autonomous reasoning, tool selection, and Human-In-The-Loop execution directly in Search.
---
### 2. Splunk Enterprise 10.5.x
> [!info] Core Focus: Machine Data Lake & Hybrid Data Federation
* **Machine Data Lake:** Economical, full-fidelity storage tier for massive log archival and search.
* **Data Catalog:** Centralized discovery and activation of federated multi-source datasets.
* **Federated Search Connectors:** Native query integration with Microsoft Azure Data Lake Storage (ADLS), Snowflake, and Dynamic Data Self-Storage (DDSS).
---
### 3. Splunk Enterprise 10.4.x
> [!info] Core Focus: Configuration Validation, Advanced Visualizations & Security Baseline
* **Configuration Validation:** Automated pre-flight syntax and schema validation for `.conf` updates to eliminate upgrade failures and outages.
* **Dashboard Studio Enhancements:** Visual *Token Manager* for debugging and new *Network Graph* dependency visualization framework.
* **Security & Runtime Hardening:** Python 3.13 standard interpreter and TLS 1.3 enforced by default.
* **KV Store Baseline:** Complete removal of pre-MongoDB 7.0 binaries.
---
### 4. Splunk Enterprise 10.3.x
> [!info] Core Focus: Edge Pipeline Templates & Observability Cloud Synergy
* **Custom Pipeline Templates:** Reusable SPL2 pipeline templates for Edge and Ingest Processors packaged as modular apps.
* **Splunk Observability Cloud Integration:** Native search and correlation across multiple Observability Cloud orgs directly within *Search & Reporting*.
* **Federated Search Filtering:** REST endpoints to configure index-based provider filtering in transparent mode.
---
### 5. Splunk Enterprise 10.2.x
> [!info] Core Focus: SPL2 Engine, Generative AI & Data Governance
* **SPL2 in Search & Reporting:** Native SPL2 execution combining SPL with SQL syntax for complex data shaping.
* **Splunk AI Assistant for SPL:** Natural language SPL query generation, explanation, and optimization.
* **Field Filters GA:** Native masking and redaction of sensitive data (PII/PHI) with full support for accelerated `tstats` searches.
* **Agent Management:** Unified console for managing Universal Forwarders and OpenTelemetry (OTel) Collectors.

---
## ⚠️ Upgrade Considerations & Architecture Guardrails

> [!danger] 1. KV Store Engine Migration Path
> * **10.2 → 10.4 :** Mandatory baseline upgrade to MongoDB 7.0+.
> * **10.4 → 10.6 :** Transition to the co-hosted KV Store architecture. Deferrable in 10.6, but **strictly required in 10.7+ and 11.x**.

> [!warning] 2. Python 3.13 Migration
> * Embedded Python 3.13 is the default runtime since 10.4.
> * Audit all Custom Search Commands (CSCs), alert action scripts, and legacy Technology Add-ons for deprecated libraries.

> [!tip] 3. Network Encryption
> * Verify that all intermediate Forwarders and syslog aggregators support TLS 1.2+ / TLS 1.3 before enforcing strict ciphers in 10.4+.
